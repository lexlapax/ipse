description: Make a bounded Ipse change with a frozen runner, explicit task scope, independent review, honest validation and safe handoff.
---

Use this skill for supervised development of Ipse or another harness. Follow
applicable AGENTS.md and the operator's task; the skill grants no permissions.
Keep the running stable harness separate from the candidate branch/worktree.
Inspect existing edits and record the baseline before changing anything.

Read the relevant implementation/tests and propose a small acceptance checklist.
Load references/evidence-checklist.md with load_skill_resource, name
self-development, before implementation. Resolve material scope choices with
ask_operator when available; a recommendation is not an answer or effect approval.

Preserve the chosen provider, model, billing and sandbox. Use only enabled profiles
and services. A smaller routine worker may analyze one bounded task when explicitly
configured; its task/context, approvals and journal remain separate. Do not assume
an installed model, download a dependency or silently fall back. Children cannot
ask the operator, use MCP or redelegate.

Make focused changes and meaningful behavior tests. Keep effects individually
reviewable, and obey the current approval policy. Inspect relevant scripts before
executing checks. For Ipse, keep its implementation/tooling in Elixir/OTP and Rust
as its repository requires; other target projects follow their own requirements.

Load references/review-request.md before delegation/review. Keep a read-only child
review to one narrow question and at most a few targeted reads; children have six
model steps and two minutes. Return unresolved findings to the parent rather than
pretending an exhausted/unknown review passed. Inspect outcomes before an explicit
new request. The parent and operator independently check the diff and evidence.

Use /diagnostics or the local diagnose CLI when retained context is large. A safe
compaction refusal preserves history; do not delete native data or repeat an effect.
For fresh-session recovery, export an explicit operator-reviewed handoff note,
inspect unknown outcomes, and use only supported recovery commands. Do not invent
an unavailable import feature or transfer old approvals into a new conversation.

Finish with the exact diff, actual checks, failures/exclusions, remaining risks and
source/package/platform evidence. Complete operator/developer documentation review
and link checks before marking work done. Commit/push only according to the task's
explicit publication authority and repository rules; honor a trial instruction to
stop for supervisor review. Loading this skill never authorizes publication.
