## Actionable finding

### R1. Low-Medium: a completed Research capture can be discarded at the prefetch deadline guard (observed)

**Location and path.** `extensions/knowledge/src/research.ex:221-226` sends a successful search to `next_fetch/1`; `:232-276` does the same after a successful fetch. At `:295-303`, `next_fetch/1` tests whether less than 1000 ms remains before testing whether the fetch queue is empty. With no queued hit, there is no next host action to time-bound. The `rank/1` and `publish/1` path at `:319-378` can return the captured result directly. Both manuals describe the 1000-ms check as occurring *before each later fetch or model rerank* (`docs/operator/research-extensions.md:154-156`, `docs/developer/knowledge-extensions.md:290-293`).

**Reproduction.** Two bounded direct Elixir probes loaded the current source with the built development BEAM path. `/tmp/ipse-p27-r1-b-probe/empty_search.exs` delivered a complete, valid `search-v1` result with zero hits and about 500 ms left of a 2000-ms investigation allowance. `Research.handle/3` returned `status: "refused"`, `gaps: [%{"code" => "time_limit"}]`, and empty coverage, rather than complete abstention. `/tmp/ipse-p27-r1-b-probe/last_fetch.exs` delivered a complete, hash-valid final `fetch-v1` body with a matching hit at the same point. It also returned `time_limit`, with no evidence or captured-source coverage. Neither probe contacted a service, model or paid provider. The current deadline regression in `test/knowledge_domain_regressions_test.exs:76-99` covers a queued *next* fetch, so it does not catch this path.

**Effect.** A successful final remote response can be reported as failed, and the caller loses its captured evidence and receipt in the public result. This changes the observed investigation outcome depending on whether the last response finishes before the arbitrary 1000-ms action threshold, even though it is within the declared total allowance.

**Minimal repair.** In `next_fetch/1`, handle `state.ctx.remaining == []` before the guard for a subsequent fetch. Keep the single remaining-time sample immediately before an actual fetch request. Add public-callback regressions for a complete empty search and a completed final fetch with 1..999 ms left; include one no-rerank case so the result reaches publication.

## Verification and code-quality warning

`test/knowledge_domain_regressions_test.exs:18-22` tests the Research deadline fix by reading `research.ex` as text, replacing its module declaration and every `System.monotonic_time(:millisecond)` call, then compiling the transformed module. The assertions at `:76-122` therefore exercise a generated module, while the two direct probes above exercise the production module. This is a brittle test seam for a control-flow boundary. A pure deadline decision with explicit `now` would permit exact 999/1000/1001-ms tests, while separate public-callback tests run the compiled source unmodified. This is a verification concern, not an additional product failure.
