### Warning — Valid overlapping-secret legacy MCP configuration cannot bind an extension action (source-only; inherited defect)

**Reachable trigger.** Configure two stdio MCP servers. The first has argument `--k=xabc` and its own environment secret `abc`; the second has environment secret `xabc`. Open a version-one journal written with the original first-server fingerprint, then invoke an extension `mcp.call` bound to the first server. The present `test/ipse/mcp/session_test.exs:320-380` proves that this exact shape is accepted for inert Session resume. The extension-specific legacy dispatch control at `test/ipse/extension/mcp_call_session_test.exs:307-340` uses no overlapping secrets.

**Consequence.** The live extension binding is refused before approval or dispatch. The operator has selected and trusted a valid endpoint and an accepted legacy session, but cannot use the authorized extension MCP action. The effect is fail-closed, so this is an availability/compatibility defect, not an authorization bypass or secret leak.

**Cause and evidence.** `lib/ipse/mcp/config.ex:86-92` recomputes version-one fingerprints from a copy without `:redactions`, as required by the historical writer. For this input the hashed argument is `--k=x[redacted]` (`test/ipse/mcp/config_test.exs:94-111`). `MCPCall.binding/2` serializes `Config.manifest/1`, whose argument is cross-server redacted to `--k=[redacted]` (`lib/ipse/extension/external_calls.ex:99-107`; `lib/ipse/mcp/config.ex:55-60,138-145`). `MCPCall.public_server?/1` then demands that the fingerprint equal a recomputation from those more-redacted public arguments (`lib/ipse/extension/external_calls.ex:286-310`; `lib/ipse/mcp/config.ex:120-135`). Those two hashes differ. `Session.Invocation.bind_mcp/5` calls `valid_binding?/3` and returns `:extension_mcp_refused` on the false result (`lib/ipse/session/invocation.ex:299-320`). Restore validation also calls the same binding validator through `lib/ipse/extension/actions.ex:612-627` and `lib/ipse/extension/effect_result.ex:355-364`.

**Age.** This is inherited, not a regression introduced at `89151b6`: `a7f4982` already computed the parse-time fingerprint with own-server secrets, cross-redacted `Config.manifest/1`, rehashed public arguments in `fingerprint_matches?/2`, and called `valid_binding?/3` in `bind_mcp/5`. The latest C1 repair correctly restores inert legacy resume; it does not close this existing extension-action path. The current P27 whole-scope acceptance and extension-MCP compatibility claim therefore overstates coverage for this supported configuration.

**Smallest justified repair.** Have `Config.manifest/1` render version-one arguments with that server's own secrets, the same representation its fingerprint hashes; keep version-two manifest arguments and all MCP description/result redaction global. `Config.load/1` already checks the own-redacted public manifests against *all* server secrets before it attaches global `:redactions` (`lib/ipse/mcp/config.ex:23-35,413-417`), so an admitted configuration cannot disclose a complete cross-server secret in that legacy manifest. Previously valid version-one binding bytes stay the same because own/global renderings already agreed for them. Check the public `Config.manifest/1` call from `Session.info` if direct programmatic `mcp_servers` maps bypass `Config.load/1`, and add ordinary and extension legacy Session action/resume controls with the two overlapping secrets, asserting one dispatch and no replay. This repairs the canonical representation without weakening saved-binding hash admission or adding a new witness schema.
