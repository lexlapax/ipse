## Before and after

The runner validated plan structure before execution, but derived individual
catalogs only when opening each project/variant Session. A declaration with an
invalid command binding in its final Research variant therefore reached the
corpus read before failing admission. The causal control supplies nonexistent
corpus and query paths. Before repair it returned a file-read exception, rather
than rejecting the unusable selection first.

Every prediction phase now derives all selected catalogs before opening a
dataset member or starting a search gateway. It uses ordinary inert artifact
import, configuration resolution, schema checks and exact command bindings.
Required verbs follow the declared preparation strategy. Freeze performs the
same check against its copied artifacts after creating the identity seal.
Frozen prediction repeats it before opening the dataset manifest.
Both frozen phases reverify their identity seal after executable preflight.

Knowledge entrypoints deliberately retain an invalid configuration as a refused
state. The first executable preflight accepted worker readiness alone, and its
negative unused-profile control still reached the dataset read. The final check
also requires an empty `invoke.command` diagnostic to return `invalid_invocation`.
A deferred configuration refusal fails that check. No host request returned by
this diagnostic is executed. Native worker cleanup must be acknowledged; a
process exit does not substitute for that receipt. The report preserves catalog,
artifact, option and export identities and individual initialization outcomes.
All selected model digests must also pass inventory preflight before dataset IO.

The CLI previously printed `status: "ok"` before exiting 1 for failed rows or
incomplete execution. It now uses the same failure condition for its output and
exit status, and includes `execution_complete` in its result. The real CLI
controls retain both first prediction rows after a source-generation refusal.
They do not retry the mutation or turn its partial predictions into success.

Resource inspection then found `persist_close/2` exporting requests through the
UI snapshot. That projection intentionally shows only the latest sixteen
requests. A new public Session control completed seventeen scripted answer
requests in one fixed twenty-request budget. HTTP dispatch count, the restored
canonical ledger and the shared budget all recorded seventeen, but the export
contained sixteen. The regression failed at that exact count assertion before
repair. The exporter now follows `Usage.order/1` and converts every validated
ledger entry with `Usage.request_record/1`. UI limits and budget admission are
unchanged. This supplies complete usage inputs for resource measurement; it
does not itself provide the remaining resource aggregates.

## Hosted formatter follow-up

The first [hosted matrix](https://github.com/lexlapax/ipse/actions/runs/39241763381)
at `b336e29693039bb4bcb965cc6cf4aa1406c43e15` failed formatting on both Ubuntu
and macOS before tests. Hosted Elixir 1.18 wraps one long readiness condition
differently from local Elixir 1.20. The follow-up stores the repeated pure
readiness match in a boolean to remove the long condition. Inlining that single
definition at its three uses and stripping syntax metadata reproduces the
complete original file's syntax tree. Initialization,
configuration probes, cleanup acknowledgments and deadlines retain their behavior.
All thirteen affected runner and Session controls passed in 129.1 seconds after
this correction. Local formatting, warnings-as-errors compilation, documentation
and pinned CI action checks also pass.

platforms. All 24 steps in each terminal job were inspected: macOS passed every
step, and Linux passed 22 with only the two macOS-only enforcement steps skipped.
This includes source tests, native enforcement where applicable, package checks,
independent source/installed MCP, embedding and knowledge proofs, and both
