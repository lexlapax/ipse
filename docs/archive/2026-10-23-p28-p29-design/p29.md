# P29 brief: provider registry, OpenRouter and Gemini

Proposal record, 2026-10-23, written against `dd510a7`. See the
[brief index](index.md) for conventions and baseline checks, and the
[plan](../../plan.md#p29-provider-registry-openrouter-and-gemini) for scope.

## Goal and boundaries

Add OpenRouter and Gemini as explicitly selected providers without spreading
provider rules further, changing saved journals, or allowing any silent change of
provider, upstream, model or billing.

Out of scope:
- Gemini or OpenRouter embeddings, which need their own evaluation;
- Vertex AI credentials (WP4 refuses them explicitly);
- OpenRouter model fallbacks and auto-routing;
- reporting OpenRouter's own credit cost as authoritative spend;
- reranking;
- changing `dev/evaluation/`, which holds frozen P27 provenance.

Adapter contract (informal; there is no behaviour module):
- An adapter exports `endpoint/1` and `complete(config, messages, tools, emit)`.
  `complete` returns `{:ok, assistant_message, raw_usage}` or `{:error, binary}`.
- It emits `{:text, delta}` for visible text and `{:provider_usage, raw}` for
  cumulative usage.
- Messages use OpenAI chat keys. The assistant result carries
  `"provider_data" => %{"provider" => NAME, ...native..., "reported_model" => M}`.
- Adapters replay native content verbatim when `provider_data["provider"]` matches.
  Otherwise they rebuild text and tool calls.
- `"openai"` is the replay key for both `openai` and `chatgpt`. Keep it.
- References: `openai.ex:89-114`, `anthropic.ex:80-103` and `ollama.ex:102-132`.
- `Ipse.Provider.Transport.stream/6` (`transport.ex:6-88`) supplies bounded
  SSE/NDJSON streaming and ignores SSE comments.

Persistence the registry must not change:
- Session metadata stores `"provider" => to_string(atom)` and
  `provider_destination` (`origin`, `target_sha256`) (`session.ex:2336-2359`).
  Resume requires the same provider string, destination and model (`:2366-2405`).
- `Ipse.Usage.restore` re-checks each admission's `billing_mode` against
  `@billing` (`usage.ex:459-460`). Existing billing strings are therefore part of
  the journal format.
- `Ipse.Provider.destination/1` and `valid_base_url?/2` reject URLs with a query
  string (`provider.ex:45-124`). Gemini's SSE endpoint needs `?alt=sse` (WP4).

Tests live in:

- `openai_test.exs`, `stream_test.exs`, `embedding_test.exs` and `error_test.exs`;
- `test/ipse/provider_test.exs`;
- `test/ipse/usage_test.exs` and its `costs` and `budget` tests;
- the `test/ipse/config/` profile tests.

There is no shared HTTP fixture helper.

## Decisions

- **D1, provider priority.** Should OpenRouter and Gemini join the priority list
  in [AGENTS.md](../../../AGENTS.md#product-and-scope)? Priority affects
  documentation order only; selection stays explicit. **Recommend** keeping the
  current four first and appending Gemini, then OpenRouter.
- **D2, generic local compatible servers.** The Chat Completions adapter could
  also serve llama.cpp, vLLM and LM Studio. **Recommend** adding provider
  `openai_compatible` with billing `local`. It requires an explicit loopback
  `base_url` and uses no credential. Remote compatible services stay refused
  until a separate change defines their billing.
- **D3, OpenRouter data policy.** OpenRouter routing can be limited to upstreams
  that do not collect prompts. **Recommend** sending
  `"data_collection": "deny"` by default. Profiles can set `"allow"` explicitly,
  and the setting is shown in `ipse config`.

Profile fields:

Request body (`stream: true`):

```json
{
  "model": "MODEL",
  "messages": [...],
  "tools": [{"type": "function", "function": {...}}],
  "tool_choice": "auto",
  "stream": true,
  "stream_options": {"include_usage": true},
  "max_tokens": 4096,
  "reasoning": {"effort": "high"},
  "provider": {
    "only": ["UPSTREAM"],
    "order": ["UPSTREAM"],
    "allow_fallbacks": false,
    "require_parameters": true,
    "data_collection": "deny"
  }
}
```

- Omit `tools` and `tool_choice` when there are no tools. Omit `reasoning` when no
  effort is set, and `max_tokens` when no cap is set.
- `openai_compatible` omits `provider` and `reasoning`.
- Never send `models`, `route`, `transforms` or attribution headers
  (`HTTP-Referer`, `X-Title`).
- Headers: `authorization: Bearer KEY` (OpenRouter only).

Message conversion, from Ipse format to Chat Completions:
- `system` and `developer` become `system`.
- Assistant `tool_calls` pass through.
- Tool results are `{"role": "tool", "tool_call_id": ID, "content": TEXT}`.
- An assistant message with `provider_data["provider"] == replay_key` replays
  `provider_data["message"]` verbatim. That includes `reasoning_details` in their
  original order, which OpenRouter requires for continuity with tool results.

Stream handling, in `consume/3` and `finish/1`:
- Parse `data:` JSON chunks. SSE comments are already ignored by the transport.
  `[DONE]` is required for success.
- **Pin check on the first chunk.** Read `model`, and the upstream field confirmed
  in WP0.
  - If `model` differs from the requested model, abort the stream before emitting
    any text and return `{:error, "OpenRouter served a different model than
    requested; nothing was used."}`. Allow only the exact equality or prefix rule
    WP0 documents.
  - Treat an upstream that differs from `upstream` the same way.
  - Any usage already emitted stays recorded, so spend is never hidden.
  - If WP0 shows that the upstream is not reported in the stream, record
    `reported_upstream: nil`. Document that routing is enforced by
    `only`/`allow_fallbacks` on the server, not observed.
- `choices[0].delta.content` becomes `{:text, delta}`.
- `delta.tool_calls[i]` accumulates `id`, `function.name` and
  `function.arguments` by `index`. Use the existing bounds: at most 32 calls and
  index 0..255.
- `delta.reasoning_details` accumulates in order into native data and is never
  emitted. Plain `delta.reasoning` is kept for replay and is never emitted.
- Map `finish_reason`:
  - `stop` and `tool_calls` succeed;
  - `length` gives the same error the other adapters use for truncation;
  - `content_filter` and `error` give a stream error, including the choice
    `error.message` after `safe/2` redaction.
- The final usage chunk becomes `{:provider_usage, usage}`.
- The result is `provider_data = %{"provider" => replay_key, "message" => %{content,
  tool_calls, reasoning_details?, reasoning?}, "reported_model" => M,
  "reported_upstream" => U}`.

## WP4: native Gemini adapter (AI Studio API key)

Purpose: Gemini with thought signatures and function-call state preserved as
continuation data.

Registry entry:

| Field | Value |
| --- | --- |
| id | `gemini`, atom `:gemini`, adapter `Ipse.Provider.Gemini`, replay key `"gemini"` |
| default_base_url | `https://generativelanguage.googleapis.com/v1beta` |
| base_url_policy | `:https_or_loopback` |
| credential | `{:env, "GEMINI_API_KEY"}`, sent only as the `x-goog-api-key` header, never in the URL |
| billing_mode | `"api"` |
| default_model | none; model required |
| secret_env | `["GEMINI_API_KEY", "GOOGLE_API_KEY"]` |

Vertex: setting `base_url` to a `*-aiplatform.googleapis.com` host refuses with
`Vertex AI is not supported yet; use a Gemini API key`. Vertex needs OAuth or
service-account credentials and is a separate follow-on.

Endpoint and destination:
- The target is `{base}/models/{model}:streamGenerateContent?alt=sse`, unless WP0
  selects the Interactions API.
- The model goes into the path, so validate it with `Provider.model_name/1`.
  Additionally require `^[a-z0-9][a-z0-9.-]{0,127}$`, strip a leading `models/`
  and percent-encode nothing. An invalid model refuses before any request.
- Change `Ipse.Provider.destination/1` and `endpoint/3` so that a registry entry
  may declare one fixed `wire_query` (`"alt=sse"`). The operator `base_url`
  must still have no query.
  - `destination` still reports the origin without a query.
  - `target_sha256` covers the full wire target, including the query.
  - Existing providers declare no query, so their digests are unchanged. The WP1
    equivalence test proves this.

Request body:

```json
{
  "systemInstruction": {"parts": [{"text": "..."}]},
  "contents": [
    {"role": "user", "parts": [{"text": "..."}]},
    {"role": "model", "parts": [{"functionCall": {"name": "read", "args": {}}, "thoughtSignature": "..."}]},
    {"role": "user", "parts": [{"functionResponse": {"name": "read", "response": {"content": "..."}}}]}
  ],
  "tools": [{"functionDeclarations": [{"name": "...", "description": "...", "parametersJsonSchema": {}}]}],
  "toolConfig": {"functionCallingConfig": {"mode": "AUTO"}},
  "generationConfig": {"maxOutputTokens": 4096, "thinkingConfig": {"thinkingLevel": "high", "includeThoughts": false}}
}
```

- Use `parametersJsonSchema` or `parameters` according to WP0.
- Include `id` in `functionCall` and `functionResponse` when the API supplies it.
- Omit `tools` and `toolConfig` when there are no tools, and `thinkingConfig` when
  no effort is set.

Message conversion:
- `system` and `developer` messages join into `systemInstruction`. Users become
  role `user` and assistants role `model`.
- Assistant messages with `provider_data["provider"] == "gemini"` replay
  `provider_data["content"]` verbatim: every part in order, including
  `thoughtSignature`, thought parts and function calls.
- Other assistant messages are rebuilt as text parts and `functionCall` parts
  with arguments decoded to objects. That includes history from another provider
  and pre-checkpoint history. Never invent a signature. If the API refuses
  unsigned history, surface the error with this recovery:
  `Gemini requires its own signed history; start a fresh session or hand off.`
  Use a placeholder signature only if WP0 finds an officially documented value
  for exactly this case. Record its source in the wire-facts note.
- Consecutive Ipse `tool` messages merge into one `user` content with one
  `functionResponse` part each, in call order. Look names up from the preceding
  assistant's call ids, as `ollama.ex:11-29` does.
- `ipse_checkpoint` compaction messages become user text parts, matching
  Anthropic's handling (`anthropic.ex:62-66`).

Stream handling:
- Each SSE `data:` object is a response chunk. Append
  `candidates[0].content.parts` to a bounded raw part list. Use the existing
  fragment limits, and cap parts at 4096.
- Emit `{:text, t}` only for text parts without `thought: true`.
- `functionCall` parts arrive whole. Assign synthetic ids `gemini_RAND_I` when the
  API supplies none. Keep at most 32 calls.
- Keep any part carrying `thoughtSignature` exactly as received. Never merge two
  parts if either carries a signature. Merge adjacent unsigned text parts only in
  the visible message `content`, never in the replay list.
- `usageMetadata` is cumulative. Emit `{:provider_usage, last}` whenever it
  appears.
- Terminal conditions:
  - `finishReason` `STOP` succeeds.
  - `MAX_TOKENS` gives the shared truncation error.
  - `SAFETY`, `RECITATION`, `BLOCKLIST`, `PROHIBITED_CONTENT`, `SPII`,
    `MALFORMED_FUNCTION_CALL` and any other reason give an error naming the reason.
  - `promptFeedback.blockReason` gives an error.
  - EOF without a `finishReason` gives an error.
- The result is `provider_data = %{"provider" => "gemini", "content" =>
  %{"role" => "model", "parts" => raw_parts}, "reported_model" => modelVersion}`.

Reasoning validation:
- Accept `low`, `medium` and `high`, sent as `thinkingLevel`. `none` omits
  `thinkingConfig`.
- Refuse `xhigh` and `max` with `Gemini supports low, medium or high reasoning`.
- Model-specific support is the API's decision. Its error surfaces with the HTTP
  hint "the model rejected this thinking level".

HTTP hints:

| Status | Hint |
| --- | --- |
| 400 | Request rejected; check model id and thinking level |
| 401/403 | Check `GEMINI_API_KEY` and that the key is enabled for the Gemini API |
| 404 | Unknown model |
| 429 | Quota or rate limit; free-tier keys have low limits |
| 5xx | Unavailable; nothing was retried |

Billing note in the manual: the same API key can be free tier or paid. Ipse
records `billing_mode: "api"` and cannot observe the tier. Operators who need
spend limits configure a rate card and budget.

Tests:
- The conformance suite.
- A thought-signature round trip: a function call with a signature, then a tool
