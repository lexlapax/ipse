# Private real Session/Host synthetic tty bridge — 2026-10-29

This is an inactive Linux integration candidate, not Review, management, or protected-output acceptance. The [plan](../../plan.md) owns milestones. It connects a genuine active selected-extension Host task and its actual Session to the [repaired synthetic native display](terminal-display-repair.md), while all production output gates remain closed. Its payload is a fixed synthetic string. Three real Transaction locks stand in for the remaining leases; their slots do not attest Identity, Consent or Collection roles. The Session input channel in the fixture has a real live reader process, but that process is a synthetic channel reader and is not proved to own the tty.

The same-owner Transaction adapter queries each native retained lock's actual process/device/inode before sharing. Its Y/K methods require the original capability owner, exact retained stack membership, one operation and original deadline, retain export order for settlement, and refuse ordinary reads, mutation, acquisition and release while slots remain shared. A missing, malformed, late or lost export/settlement reply stops the transaction with an unknown result. Native Y/K still independently authenticate transfer, retain descriptions and settle each endpoint. The native per-owner 256-operation limit remains; no rotation or production activation is claimed. The additional native I command provides identity only; it is not an output admission.

The Host asks the Session for its ordinary private ticket, opens its own control, and receives the Session's separately owned control and sealed Writer snapshot. A new asynchronous guard request supplies the exact existing Session lock owner/device/inode without a release/reacquire window. The bridge creates fresh private bindings for the matching native tty, actual owner controls, Session lock and three Transaction slots, and sends the immutable synthetic manifest and payload. The same setup deadline gates every adapter phase. The native guardian and forked reader hold all descriptions through bounded direct tty writes; D is only native write progress, not operator observation or authorization.

An initial genuine PTY run exposed a close-order problem: the guardian dropped its owner peers before sending final C, allowing an owner-control sender to exit and poison the Session before thaw. The repaired synthetic protocol sends C only after reader reap, guardian lock drop and all exporter settlements, but retains both owner peers until an exact operation-bound U from Host. After receiving C, Host asks Session to enter a still-sealed terminal-closing phase, sends U, observes native and Host-control exit, waits for Session's own clean control exit, and only then requests Writer thaw. Any failure, missing reply or deadline loss remains unknown. The existing generic Session finish path and Host-internal close request trust the original Host's sequencing; Session does not independently authenticate the native C or attest the three management roles. This is an explicit blocker to protected activation, not a demonstrated adversarial same-VM security boundary.

## Focused controls and provenance

The final matching graph passed two actual Session/Host controls with a selected artifact, admitted worker action and real PTY: full fixed-synthetic display, four retained descriptions, ordered settlement/owner closure and thaw; and exact Session lock identity with foreign-caller and premature-close refusal. Two direct Transaction controls passed actual three-slot transfer/ordered settlement and recipient-loss unknown, with a foreign capability and frozen mutation/release refusal. The affected native real-PTY four-lease display, inert normal and short-manifest refusal also passed.

The separate actual Session cancellation test pauses the synthetic adapter before activation, stops both native reader and guardian, suspends Writer, and calls Session cancellation. Cancellation returned promptly. After the actual Host and Session died, the guardian was killed and both original native lock owners had exited, contenders remained blocked on all four descriptions held by the stopped reader. They acquired only after the reader resumed and exited; the captured output contained no synthetic payload. A first attempt observed an original owner still alive after 1.5 seconds and failed its fixture assumption; the passing test waits for actual owner exit rather than inferring it from BEAM death. This is a pre-activation cancellation control, not evidence for every post-write loss or Review phase.

The [evidence](evidence/tty-session-bridge/) retains the final source tar, exact native helper and PTY fixture binaries, relevant BEAMs and complete runtime hash inventories for the uninstrumented graph, positive/identity Host-rendezvous graph and cancellation Host/bridge-rendezvous graph. It retains the initial missing decoder tags, helper-boundary, FIFO-stat and close-order failures and the synthetic-only diagnostic source/markers. The selected fixture artifact was cleaned up by test teardown and was not retained; its digest was admitted at runtime but this archive cannot independently reconstruct that exact artifact. The passing cancellation case's body is unchanged in the retained test file, but the exact whole-file snapshot from that run preceded a later independent identity-test insertion and was not saved. These provenance limitations do not alter the observed controls and prevent a claim of a complete frozen artifact cohort.
