# Private Session and Host control wiring — 2026-10-29

This candidate extends the [native owner controls](owner-controls.md) and [inactive Host/Session sharing](session-host-share-independent-review.md). It is not a production call site or guarded-output acceptance. The [plan](../../plan.md) owns acceptance, and all protected-output gates stay closed.

For the inactive controlled path, the actual active Host task requests a one-use Session ticket tied to its current job, exact admitted action, selected extension identity, original operator channel and a single five-second setup deadline. The Host verifies the pinned helper outside Session, prepares that ticket and action, opens its own Port, and waits for its sender readiness. Session checks the same caller, job, action, ticket, channel and Host Port ownership, then opens its own Port and asynchronously seals the Writer. It handles native readiness and the Writer/guard replies independently; the Host receives the capability and source snapshot only after both are ready. Preparation accepts the fixed pinned application helper path only. The hash precheck follows the existing cooperative same-user filesystem model; it does not atomically prevent another same-user process replacing the executable between verification and exec. Preparing and spawning are not claimed to be hard-preemptible filesystem or kernel operations.

After matching Host configuration, Session handles bounded fragmented `R`, `H` and `T` frames for its own Port in order and checks the operation, role and original deadline. `T` reports transfer only. Foreign calls, a stale or altered preparation, malformed/out-of-order frames and late replies do not authorize progress. The one-use ticket is consumed when Session starts the seal or refuses a matching attempt. Unknown messages, loss of the bound channel reader, cancellation, timeout and other failure poison the seal. Poison first closes the actual Session-owned Port and kills the actual Host task, whose own Port closes with it; it does not wait for the suspended Writer or report uncertain native IO as stopped. A late frame after poison is ignored and cannot restore progress. Before a pre-export abort or final thaw, the Host closes its own Port and Session confirms that closure, then closes its own Port. This is not an all-copy native recipient-closure proof and does not authorize terminal input or an effect.

The operation is private same-VM host machinery. No production journey calls the new controlled Host adapter. Session and Host APIs, executable identity and Port ownership are not intended to defend against hostile code executing inside the trusted host VM. The captured input-channel reader is real in these fixtures but is not a validated matched tty. The Host-side later `H`/`T` completion parser, terminal payload binding, Session/Host guardian handoff, exact owner EOF integration with a real native tty writer, all four management leases, forked reader/guardian close and final Review consumption remain open.

The standalone management command has a CLI parent and file-effect journal owner, not this conversation Session/Host pair. Its native journal layout does not claim Session release semantics, and its existing header_v1 lock cannot be closed and reacquired to simulate export. This candidate does not qualify management review or its four-lease journey.
