# Document producer source policy at inference egress — source investigation

Read-only investigation, 2026-10-29. No runtime, native, gate or test changes were made for this record. The [plan](../../plan.md) owns acceptance. This concerns the first-page `collection-dense` producer, not all embedding callers or managed-note inference. The separately reviewed [producer design](shared-producer-v1-design.md), [first-page evidence](shared-producer-first-page.md), and current source remain distinct. This is a proposed interface and ownership boundary, not an implemented or verified authorization.

The [source snapshot](document-producer-source-egress-gap/source.tar) and its [hashes](document-producer-source-egress-gap/source.sha256) pin the 28 inspected files, including the contemporaneous optional embedding-selection source. They are a source-only snapshot, not a runtime cohort or proof that all concurrently changing worktree files were captured atomically. The optional selection pin belongs to separate in-progress work and is not assumed to have been released by this investigation.

## Current boundary and the gap

The knowledge extension's `Store.Collection.Producer` derives its pending v2 `ipse.evidence.shared_producer.first_page.v2` record from the actual selected catalog page, source heads and reconstructed source bundles. It checks source eligibility before claim and before each worker-requested inference batch. Its pending record binds partition; Job ID and revision; catalog hash/floor; selected root revision/hash; cursor and vector/fact selections; an ordered source set; each source head's actual revision/hash, bundle hash, claimed observed/expiry/historical fields and chunking hash; and up to eight ordered rows `[source ordinal, chunk ordinal, chunk ID, canonical input hash, raw input hash]`. Two source chunks at most enter one embedding request. The record is bounded to 8 KiB. These are useful expected facts, but the record itself is stored by an extension request and is not a Host-issued source authority.

Each `collection.store` read or mutation goes through an operator-selected documents binding and existing project Identity, Session/action and registry checks. `DocumentStage` reads at a native Collection generation and its commit uses a Collection CAS. Those requests are separate lock acquisitions. `Collection.ReadView` explicitly retains no descriptor; each read checks a current root and then releases its native owner. `Collection.with_managed_read` does retain an owner, but it is notes-profile-only and caps its closure at 32 read units. None of these APIs presently validates the complete document source set while retaining the document root across a later provider send. In particular, a source head binds the bundle hash but does **not** contain `observed_at_ms`, `expires_at_ms` or `origin.historical`. Copying those fields from the worker's pending record, or merely comparing the head hash, would not establish their actual stored values.

After the producer's last worker check, normal extension approval can wait. The source can expire, become historical, or be replaced before the actual inference body is sent. `Session.InferenceDispatch` currently constructs a managed snapshot from managed-note dependencies, and `InferenceDispatch.managed?/1` selects `MintOwned` plus `EgressGate.capture_owned` only when that dependency list is nonempty. The document producer does not create a Host-owned document dependency. Consequently its ordinary `embedding.create` cannot rely on the existing managed-source send callback to hold its document source/root ownership. An ordinary pre-send timestamp or worker-selected deadline would still leave the wait and check-to-send race. A producer-specific fail-closed gate is warranted until the actual Host boundary exists; unrelated embedding callers need not be disabled.

The current source also supports an optional v2 `expected_selection_sha256` in the generic embedding binding. That pin is part of separate, currently developing bootstrap/selection work; it must be supplied and checked at the selected profile and actual serialized egress, but it does not establish source eligibility. The worker producer's existing local comparisons and response checks are not a replacement. The active route must not silently take the unregistered inference branch, which bypasses the owned dispatch path.

## Smallest reviewed extension boundary

The extension should continue to define its document schema, input order, source eligibility and versioned chunk recipe. A reviewed operator/artifact binding must additionally identify an explicit, bounded declarative source-use recipe for this producer. A Host-owned interpreter may perform only the limited structural operations needed to load packed document values, assemble ordered bundle pieces, select fields, validate types and hashes, evaluate the declared time rule, and reproduce the approved deterministic UTF-8/segment chunking and chunk ID. Do not load or invoke worker-supplied code inside a Host lock callback. Current `ManagedRecipe` is a closed literal-note/proposal extractor with a different source-proof model and cannot express this multi-record bundle/chunk relation; `collection_binding` currently selects the document profile only. An equivalent equally reviewed mechanism is acceptable, but a claim, arbitrary JSON path or unreviewed callback must not become authority by itself.

Bind the reviewed recipe digest, actual operator-selected artifact/instance and invocation descriptor, exact project/worktree binding and document namespace/profile, Session/client/job/action and active registry identity. The producer's claim must be connected to the same live invocation that received its actual confirmed claim CAS; a stored pending record or resumed journal is never a continuation token. The Host tracks the ordered batch position in that volatile owner and advances it only after a confirmed matching action outcome. This prevents another job, another client, duplicate/reordered batches, or a worker-selected record with matching-looking text from adopting a pending claim. The durable intent should bind the original action, source-set/recipe and wire digests in a versioned replay-validated shape; an interrupted prefix remains unknown and cannot dispatch or reconstruct the volatile capability.

For the claim CAS, a Host-only fixed-profile retained-read/precondition hook must check the authoritative catalog page, Job/root/claim stage and complete current bundles at the same Collection generation and native owner that admits the original CAS. A prior Collection read followed by a later CAS is not enough. The hook must use a Host-selected reviewed recipe and a one-use owner/action binding; workers cannot pass a callback. Its checks and normalized original commit remain inside the same native lock and existing generation/revision CAS, and current UTC must satisfy `observed_at_ms <= now`, `historical == false`, and `expires_at_ms == nil or now < expires_at_ms`. Finite TTL remains supported when current. Existing stage ownership, reservation, deadlines and unknown/no-replay rules remain intact.

After each actual embedding approval and immediately around its actual send, reacquire the existing project Identity and the documents Collection owner in the established order. Under that retained native owner, rederive the exact pending claim and revision, catalog and selected root, complete catalog membership and head revisions/hashes, every source bundle and source-set digest, metadata times, chunking/segments, source/chunk ordinals, raw bytes and canonical hashes. Match the exact next one- or two-input embedding action, registered route/model/profile selection and serialized request-body hash to the current Session/action/approval and the prepared wire. Then sample the Host UTC clock again immediately before the one-use real send. Hold exclusion through the bounded admitted send and its writer-quiescence boundary; after a failed or late reply report unknown where a send may have occurred. An already admitted send can finish after an expiry or cancellation; this contract does not promise physical recall of buffered network bytes.

The source bundle is authenticated here only as the actual bounded content of the retained operator-bound Collection and its current root. Its embedded timestamps and origin are the stored source's values, not independent proof that an external document or author made them. This producer route needs no invented current original-Session source lease solely because an unavailable fixture mentions one. If a mixed managed-note/document invocation is later supported, its actual source/Consent and both Collection ownership requirements need an explicit combined lock order and capacity proof; current single Collection process marker prohibits naively nesting two held Collection callbacks. Until that is designed, refuse the mixed path rather than dropping either dependency. The treatment of displaying full approval arguments as a separate protected-use boundary also needs explicit policy/ownership review; an egress guard alone does not establish that display.

## Bounds and transport ownership

The existing first-page shape admits up to eight source heads and 32 data-block references per bundle. A single pinned verification therefore may require up to 256 distinct data records plus four catalog/root/Job/pending anchors, one catalog page and eight heads: 269 logical records before any stage/closure-specific extra reads. Each underlying document record can occupy up to 64 KiB, so a conservative record-value read ceiling for those 269 records alone is 17,629,184 bytes; assembled source bundles are separately bounded at 1 MiB each, with source text at 65,536 bytes each. These are upper arithmetic bounds, not observed peak memory or an admission result. Count actual native reads and decoded/escaped bytes, deduplicate only identical reads under the same retained lock, explicitly account for manifests, per-bundle assembly, JSON depth/duplicates, stage reads and process overhead, and fail closed before exceeding a chosen reviewed bound. Do not silently reduce the supported eight-source contract to fit the existing 32-unit notes callback. Internal bounded JSON assembly is required: an SDK wrapper's 8 KiB scalar limit cannot represent a 65,536-byte source.

Reusing `MintOwned` and the existing one-use `EgressGate` is attractive because the latter binds actual target/body hashes, same caller, upstream liveness and one continuation. It is not sufficient merely to put the new disk-backed callback inside the present controlled sender. `Resources.controlled_owned_effect` may kill its peer, and explicitly excludes arbitrary file-server IO; `Resources.file_effect` inside an already active effect runs inline. A killed peer's native lock can close while independently pending file-server or TLS/socket work is not yet proven quiescent. Conversely, the Mint `send_once` closure is same-process and cannot simply be invoked by a different lease peer. `CompletionWitness` verifies normal observed close but does not establish an independent close receipt after every killed sender or unconfirmed SSL cleanup.

A narrow Host resource seam is therefore also needed: an independently tracked, non-killed file/lease owner retains Identity and the document Collection while the exact owned transport child performs its one-use request; the owner releases only after an actual matching send/child/socket quiescence acknowledgment, not an ordinary process message or a timeout. A loss before admission refuses; loss during/after an admitted write is unknown and the owner must retain/quarantine the affected leases until the actual writer and socket are known quiescent. No cancellation byte, later reacquisition or successful slot reservation proves close. The existing `controlled_owned_effect` timeout/unknown return cannot itself serve as that all-writer-close acknowledgment. The exact supported TCP and TLS/SSL cleanup semantics and the ability to retain the existing native lock through uncertain cleanup must be proved with real owner-death/backpressure tests. If those properties cannot be established without a new native primitive, the requested no-new-native-API scope is a concrete blocker and the producer must remain gated; this record does not claim otherwise.

## Focused acceptance for an implementation

Exercise actual operator-bound current storage and a real local registered provider. Cover: one eligible finite-TTL source through claim and send; expiry during approval with zero request-body egress; `observed_at_ms` in the future, historical source and expiry equality; head-only forged times; malformed/duplicate bundle and mutated head, block, catalog, Job, root, chunking, input order and route after claim; pending-claim adoption and cross-client/replay refusal; full eight-source bounds and late clock movement. Preserve exact unmodified root and no provider body on pre-send refusal. Separately stop or kill the actual Session, Host, source-check peer and transport at pre-admission, in-flight send, socket close and response boundaries; an independent Collection writer/revoker must not complete before the old sender is quiescent. Observe TCP and supported TLS cleanup independently, with lost acknowledgments classified unknown and no retry. Finally verify the combined approval, claim, dispatch intent, actual wire and result journal chronology and unchanged unrelated embedding callers. These are prospective tests, not evidence obtained in this read-only investigation.
