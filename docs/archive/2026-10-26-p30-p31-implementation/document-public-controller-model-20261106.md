## Implemented developer path

The request ledger now follows the actual public Corpus controllers for Source
construction, lexical indexing, bounded fact publication, selected-result
assembly, producer pages, bound append and compact finalization. Native storage
and embedding replies remain explicit in-memory fixtures. Fresh modeled generation
and operation accounting start at zero; no synthetic generation offset is charged
as missing lifetime operations.

Each fact input publishes within the unchanged Worker frame. Assembly selects
those closed codec descriptors in the actual catalog-page order and preserves
every source and fact row. Its read actions use the production intent/result
codecs, final action count/digest and sealed result reconstruction. This is modeled
producer-Session metadata, not an actual Session lease, native grant, original
source proof or managed delivery. The reducer counts publication codecs separately
from action pairs; assembly action-codec bytes are an existing subset and are not
added twice.

The model checks request/outcome/frame validators and its declared operation,
record and per-invocation bounds. It does not model native transaction allocation,
flat-manifest admission, checkpoint/import union, complete Session journals or
end-to-end permission/currentness. No original retained notebook, real provider,
native store transaction or terminal review ran in these controls.

## Profile and rejected cache experiment

OTP eprof used a Model MFA selector. OTP also traces newly loaded modules through
`on_load`, so the result includes newly loaded JSON libraries while previously
loaded Knowledge work remains attributed to its Model caller. The profile recorded
824,209 `JSON.encode!` calls, including 70,037 Model JSON calls, 5,328 descriptor
calls and 6,165 observations. JSON escaping and the public controller's caller
accounted for substantial time; exclusive descriptor timing could not identify
its nested serialization cost.

A narrowly scoped cache therefore received a controlled experiment, not automatic
adoption. It stored encoded bytes/hash only in the occupying model record row,
with exact value and revision guards. Repeated reads, changed value at the same
revision, revision-only collision, actual overwrite and the record-key bound
passed. A model-only hook reused the exact real action identity in the shadow,
including actual intent/result validation where present. This preserved head and
operation identities instead of merely masking their reply fields.

One actual eight-source controller sequence supplied identical requests to both
backend variants. The timed replay order alternated. All 6,165 full replies,
logical values, revisions, stages, heads, operation identities, protocol counts
and frame lists agreed exactly; no field normalization was needed. The callbacks
outside the Native mock executed once and their exact bookkeeping was shared by
both variants; their independently accumulated stores were never copied.

Backend work measured 1.977 seconds without the cache and 1.601 seconds with it,
a 0.376-second reduction in a 33.052-second instrumented complete group. This is
not an independent whole-pipeline timing comparison. The small absolute saving
did not materially resolve the target's throughput problem, so the cache, fixture
identity hook and experimental test additions were removed. Their exact source
preimages and failed/passing results remain private. No performance machinery or
full-target retry was adopted.
