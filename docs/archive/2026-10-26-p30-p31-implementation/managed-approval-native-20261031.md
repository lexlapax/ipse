## Implemented boundary

`Session.ManagedApproval` binds the actual pending ordinary model call, original
arguments, request, canonical dependency union, full escaped payload and fresh
one-use input challenge. Subscriber events carry content-free status, not those
arguments. The Session chooses the native Port and payload for a separate typed
purpose; an extension job or standalone management permit cannot substitute.

Fresh Linux Sessions and framed resumes use the existing share-capable header
and resume owners. They retain the original flock without a close/reacquire
upgrade. The actual Writer drains and seals active proofs and inactive original
lock identities before sharing. The protected callback retains actual
Identity/domain, Consent and Collection owners and every original source group;
its final root must reproduce the authenticated observations. Native v13 checks
the Session/Host controls and complete manifest and delivers the bounded full
payload under those exported owners. Nothing truncates the 64-KiB display.

Display completion, every exporter settlement and the Session notice precede
Writer thaw. A private same-process continuation keeps the enclosing file-effect
owner and controls alive while the source/policy scopes release. Only then does
the host send `U` and begin native input. The v13 final exchange now watches the
Session/Host controls rather than requiring settled source exporters to remain
alive. Display ownership checks and all close handshakes remain required.

Only an exact fresh `allow CODE` authorizes one attempt. Denial and a stale code
start no tool; `/cancel` and `/exit` use ordinary cancellation and clear queued
prompts. Before execution, the existing managed-effect adapter reacquires current
authority. Changed original bytes and revoked permission therefore prevent the
write after an otherwise confirmed approval. Lost ownership poisons and stops
the approval Session; unconfirmed task cleanup retains the existing stop path.
Resume never reconstructs an approval grant or repeats an interrupted effect.

The input service confirms restoration/exit of its old native reader before
display starts. It preserves staged queued prompts, keeps one-use release
tickets bounded to 64 globally and one per target for five seconds, and retains
a bounded cancellation acknowledgement if native cancellation beats the client's
await. Ordinary legacy cancellation retains its earlier result. The CLI keeps
its reader generation across the approval handoff instead of racing a replacement
reader against the retrying original.

## Actual controls and retained failures

The final production-adapter cohort covers eleven native-terminal scenarios using
the normal knowledge setup and three actual native statement/category captures,
then a consuming Session with the registered synthetic local HTTP route.
One control keeps the original source Session active as the consumer; the others
close it before starting a fresh consumer. It covers fresh, active and resumed
writes, deny, stale challenge, cancel, exit, delayed
input beyond the display interval, altered original source, revocation and Session
death. Each input control separately acquires Identity, Consent, Collection and,
for inactive originals,
the original source lock during the input wait, proving release of those display
owners. The active-original control retains its ordinary conversation flock while
proving release of policy locks and successful result continuation. The tests
check the actual output file and preserved original history. Inactive originals
remain byte-identical except for the explicit controlled alteration; active
history retains the original prefix and appends the consumer turn. Saved
reconstruction, final request accounting,
settled service slots and confirmed close where the owner survives. The source
alteration is inspected unchanged before the fixture explicitly restores it.

These are automated PTYs and synthetic model responses. They establish actual
native origin and the production adapter, not human authorship or model quality.
The private fixed-text v13 active-only and mixed-source controls also pass when
run independently. A native input control exercises cancellation before await,
one-use release, duplicate refusal, preservation and one-use submission of an
already staged prompt, plus the existing terminal observation lifecycle.

The first runs are retained in the receipt. They found the old production lock
selection, fatal reader retries during the frozen phase, empty-active-proof
barrier refusal, a strict-boolean cleanup bug and the final-notice watcher that
still required released source exporters. Repairs preserved the safety checks.
The active-original control then exposed two further defects: its post-display
proof recheck reached the frozen Session gate, and successful result publication
advanced the global source index generation. A narrow approval binding now permits
the former check after Writer thaw. A result-only postcheck permits monotonic global
generation advance while freshly revalidating identical selected proofs, window
and policy. Source tests retain refusal for redaction, policy changes, window
replacement, rollback and index additions in approval/effect scopes. The original
negative active runs remain retained, including the write followed by unknown
result; the passing active journey requires normal result continuation.

Fixture failures are separate: early input/exit before native readiness, fixed
synthetic challenges reused across one driver, CLI consumption of fixture task
results, and an immediate process-death assertion after a completion marker.
Collectors, native readiness checks and a bounded exit monitor repair those
fixtures without converting required positives to refusals. Two development
runs overlapped before their terminal status was checked; they are negative
diagnostics, never qualification evidence. Final qualifying PTY runs are serial.

Exact test/build/check results, source hashes and all available diagnostic log
hashes are in the receipt. The existing full-source negative result remains
unchanged: 3,538 passed, 60 failed, 109 skipped and 112 excluded at `e86b1b8`, with
its recorded concurrency and source-inventory timing limits. Focused passes are
not subtracted from that result or reported as a new full-suite total.

## Scope review and remaining work

The implementation review traced pending-call and purpose matching, full-payload
ownership, native settlement before release, source/policy release before input,
one-use completion, fresh effect admission, cancellation, queued input and unknown
cleanup. It found and repaired the cleanup-result dispatch ordering before final
controls. This is a development review, not the goal's independent adversarial
audit or final reviewer handoff.

Accepted-decision v6 dependencies still require their additional original
management journal at the display sink and refuse this adapter. Delegation,
nested worker approval displays, unqualified protected result pipes and clients
without the native channel retain their gates. No 128-note, all-HTTP-fault,
installed-package, macOS or independent quality acceptance is implied. The display
deadline remains a checked native IO deadline, not a kernel-atomic expiry/write
guarantee. Current inference and effect deadline contracts are unchanged.

No new dependency or native wire format is introduced. No real inference,
metadata-service request or model download ran in this increment. Allowances
remain ChatGPT **238/300 conservatively charged** and local **4/1,000 charged**.
The developer and operator chapters were reviewed whole, stale ownership/refusal
descriptions reconciled and their entry points updated. The full P30/P31 goal,
whole-current qualification, independent audit and reviewer handoff remain open.
