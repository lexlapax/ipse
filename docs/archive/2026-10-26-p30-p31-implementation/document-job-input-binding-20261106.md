# Document Job input binding component, 2026-11-06

This record covers a synthetic component check of an opt-in shared-generation
Job binding. It does not describe a public Corpus command or an operator
approval journey. The current public procedures and limits remain in the
[Corpus manual](../../operator/corpus.md); milestone status is in the
[plan](../../plan.md).

The private Job format starts with an empty binding and, after vector preparation,
can bind an exact selected-result digest, raw body digest, source group, cursor,
pre-binding physical Job revision and stable project, Session and extension
identity. A guarded group advance clears that binding; the last group returns to
the existing completed Job format. A bound Job cannot acquire a new model request
through the checked source-use path. The reducing abort keeps the original epoch
and requires the stored owner. Historical Job formats remain separate.

The native check used a disposable private store and synthetic supplied sources,
vectors and selected-reference digests. It created a version 7 Job through the
actual Job controller, bound it, and completed a one-group append into the
existing final Job format. A second Job was created at maintenance epoch 1 in
version 8, bound, and then subjected to an actual catalog change and a further
epoch fence. Its old append was refused without a changed observed snapshot; the
same owner then completed a reducing abort. For guarded commits, the test called
the real source-use authenticator through a retained native reader before the
actual staged store operation. It also checked altered input digests, owner,
generation and synthetic stale/missing-reader cases, with the observed store
snapshot unchanged by those refused checks.
