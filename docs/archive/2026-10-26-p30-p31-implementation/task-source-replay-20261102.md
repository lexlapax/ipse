# Task-scoped source replay, 2026-11-02

This increment follows the [failed batched-read probe](recall-batched-read-20261102.md) and the [earlier replay work](recall-replay-capacity-20261102.md). It reduces repeated reconstruction of an unchanged inactive source; it does not complete the [notes journey](../../plan.md#p31-usable-knowledge-and-prompt-assistance).

`StoredSources` still opens and locks each original journal, scans it, verifies its recorded origin and project, validates source pages, resolves every requested proof and checks ownership again after use. Within a task's cleanup scope, `SourceReplayCache` may reuse an index only after it has itself successfully run the complete `Saved.restore/2` on the same Session ID and deterministic decoded events. It stores no source lease or consent. Each cache hit creates a fresh window identity and secret. Scope closure and owner loss terminate the cache.

The cache accepts at most one queued cached reconstruction, rejects cache admission for event lists over 8 MiB before sending them to its process, and otherwise falls back to ordinary reconstruction. It retains at most 128 indexes with 8 MiB total encoded size. An encode/decode copy detaches retained source fields from larger journal read buffers. The encoded-size budget is not a bound on total BEAM heap or transient copies. If a cache caller is killed while holding the admission gate, later calls in that scope reconstruct normally rather than waiting or trusting a partial result.

Focused cache/source tests cover changed same-size source content, a copied journal at another inode, invalid cache insertion, changed events and Session IDs, fresh window secrets, bounded retention, oversized and contended bypass, and a stopped owner while the cache is suspended. A wider protected-source, lineage, worker-input and ordinary native recall cohort passed **132 tests, one skipped**, seed `791946`; this was a `--no-compile` run against the already compiled test build. A static independent review identified the pre-IPC and retained-buffer bounds subsequently addressed here; it found no additional concrete authority or cleanup bypass in that limited review. This is not the final adversarial audit.

On the retained 33-note synthetic source, the task-cache diagnostic using the existing 32-note worker delivered all 36 recorded protected worker inputs but closed a synthetic provider connection before request bytes with a configured 5,000 ms provider timeout (seed `791940`). The trace recorded managed preflight and inference intent; it does not establish the exact cause of the close. With an explicitly configured **15,000 ms synthetic provider timeout**, the existing 32-note partial selection completed through the native Session, provider request, Saved reconstruction and confirmed close (seed `791947`; one passed, two excluded). No live model or human review was used. Concurrent work in unrelated document files means this is a scoped built-artifact control, not a frozen full-tree acceptance run.

A separate temporary 96-indexed-candidate experiment reached the synthetic provider but included only 32 of 33 notes; it was removed. Its asserted fitting expectation was wrong: the [frozen projection](recall-fitting-envelope-20261102.exs) measures 8,223 bytes for those original texts against the 8,192-byte envelope. The shorter replacement fixture measures 7,794 bytes in the same pure projection but has not completed its native journey. More fundamentally, a fixed indexed-row cutoff cannot prove fitting-set coverage when earlier rows have unavailable sources. The 33-note fitting journey, larger eligible-set discovery, the 5,000 ms provider control, in-chat proposal acceptance, final integrated tests and the P31E gate remain open. The existing automatic selection limit remains 32.
