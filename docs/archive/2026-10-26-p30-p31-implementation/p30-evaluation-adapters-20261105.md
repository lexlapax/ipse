## What this increment supplies

The candidate-assessment declaration binds inputs, source receipts, baseline
observations, finite limits and routes before exposing labels. Pending proposals
and observed-durable cases remain separate strata: pending advice cannot count
as reduced false-durable capture. The optional single-case Session owner is OFF
on load and requires an explicitly enabled reviewed entry. It uses existing
source checks, saved consent, native approval, accounting and release owners.
Typed denied, refused and cancelled observations require their causal joins;
unclosed or partially observed work stays unknown. Advice-phase duration does
not become matched whole-task latency, and unobserved cost remains null.

The protected-answer adapter joins actual recorded reads, a complete engine-free
answer, selector output and candidate answer into the existing selection study.
The baseline must be generated and frozen before selection; candidate preparation
reprojects that actual baseline and requires exact equality. Both arms use the
same declared helper execution. Complete baseline membership supports up to
sixteen records, while selected packs retain their four-record limit. Existing
version-four context and complete SDK-envelope bounds refuse overflow without
trimming evidence.

Historical provenance reconstruction retains every original read dependency,
additional inherited dependencies and the actual baseline entry union. The
delivered WorkerInput and helper preflight must bind that union. Supported
selector commands can materialize complete paged results; answer services retain
their existing inline-result contract. Answer citations join exact note-text
and answer UTF-8 byte spans, revisions and hashes. This establishes byte
integrity of attributed derived text, not original-source quotation, entailment,
independent review or a fresh source lease.

answer journey has not run with these adapters. Actual assessment materialization,
