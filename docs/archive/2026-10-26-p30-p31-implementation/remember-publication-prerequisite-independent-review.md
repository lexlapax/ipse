## Exact supported predicate

Retain the complete host-owned invocation union and active-parent binding.
Require zero inherited invocation input. For **every** dependency, require a
validated version-3 `root_observation` at the expected project/namespace, exact
current pin digest and policy epoch. Find its own authentic committed successful
current-parent `collection.call` result, with the matching read operation/action
and exact read binding. Reuse existing closed Actions/ManagedReads validation;
worker-returned lookalike JSON or a result from another invocation is insufficient.

Only two public inner operations qualify: `snapshot`, whose closed result has
no record values, or `get`, whose closed result contains exactly `record: nil`.
Require that dependency's subject to equal the digest of **that** inner request
and **that entire** result. Match result project/generation/floor/anchor to the
dependency and publication binding. Require all qualifying dependencies' complete
collection maps to be identical, including project, generation, floor, floor
anchor, root state, root hash and manifest hash; generation must equal the proposed
commit's expected generation. The full root identity comes from authenticated
host observations, not by inventing missing hash fields in the public summary.

Do not filter the union to a convenient subset. Any inherited input, record-valued
get, record-observation dependency, scan/index, unmatched/foreign/failed result,
wrong pin/policy, mixed root or expected-generation mismatch refuses. Equivalent
repeated reads may share a normalized dependency; a new one-to-one multiplicity
protocol is unnecessary. Current storage freshness is still decided by the real
protected source/policy and native Collection CAS path. A self-consistent old
generation request may reach an intent and then conflict; this pure prerequisite
must not be described as a later-use authority or a disk-currentness check.

Nil absence contains no record bytes. An arbitrary otherwise admitted public key
therefore needs no `note.`/`override.` hardcoding to satisfy this root-only rule.
The request's ordinary key validation, scope/exclusions, actual recipe,
normalizer, exact original-source proof and signed metadata checks still determine
whether its proposed publication is allowed. The absence itself grants none of
that authority. Record values remain disallowed even if the host happened to label
their dependency `root_observation`, as can occur for a nonliteral public record.
