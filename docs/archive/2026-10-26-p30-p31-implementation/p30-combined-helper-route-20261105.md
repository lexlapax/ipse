## Behavior and authority

`knowledge experiment advice CALLS [SECONDS] --helper-profile PROFILE` explicitly
includes one existing `model.complete` profile alongside main and advice. Without
the option, the old two-route policy is strictly preserved. Configuration alone
can define profiles and service origins but cannot add a route to protected
permission. The CLI reuses actual SemanticRoutes review, final Activation/Registry
Knowledge identity derivation, complete native confirmation, configuration
revalidation, identical repeated preparation, ProjectIdentity and Consent epoch-CAS.

The helper requires a separately imported, trusted and selected `host.model`
extension. Neither shipped Knowledge preset has that capability, and no capability,
helper outer effect, source fence or Consent codec changes. Ordinary helper
approval, Usage/Budget and service reservations remain separate. CALLS still
counts decisions only, not helper/main requests or money. No provider, endpoint,
billing mode or fallback is selected implicitly.

The public generic `model-calls` example provides a separately buildable command
artifact for the ordinary SDK effect contract. It is not the projector's
`answer_context` service or an out-of-box protected-note answer strategy. The
[earlier paired protocol](p30-paired-protected-answers-20261105.md) used a disclosed
trusted three-route setup; it does not establish this new CLI-to-paired path.
