# Private first-use MCP draft checkpoint

Historical experimental evidence, 2026-10-27. This is a private prototype, not production behavior or milestone acceptance. It supersedes the preload requirement of `draft-mcp-revalidate-v4.md` and applies to commit `52652f825e7437ac32ac630092b69095d2049a3c`; current scope is in `docs/plan.md`.

The first draft in a Session with configured MCP now begins its journaled draft interval before configured catalog discovery, retains the witnessed input within that interval, records a setup intent before the connection, and pins the resulting catalog to a reference admission before the first model request. A synthetic local server's raw discovery RPC trace was checked for the draft canary. Additional synthetic Session journeys cover owner death during a blocked first discovery and first-use question/restart followed by fresh catalog revalidation. Owner loss while discovery is in flight blocks automatic replay and cancellation records the outcome as unknown. A crash after discovery has produced an observed result but before the catalog snapshot is pinned blocks recovery until explicit cancellation; the intermediate journal prefix was checked synthetically, not by killing the process exactly between the writes.
