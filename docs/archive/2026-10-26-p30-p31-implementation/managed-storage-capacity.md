# First 1,000 actual managed publications

Dated synthetic investigation, **2026-10-26 Pacific time**. This measures the
current managed Normalizer's real metadata and version-5 receipt overhead after
the [ordinary-v4 annual attempt](storage-annual-s1-incomplete.md). It does not
complete the 2,000/4,000-note capacity targets, annual turnover, P31C1a, E or
default enablement. The [plan](../../plan.md) and
[qualification protocol](qualification.md) retain those gates.

## Exercise the actual managed interpreter

The [entry point](../../../dev/knowledge/managed_storage_workload.exs) and
[driver](../../../dev/knowledge/managed_storage_workload.ex) create a new protected
Btrfs store and call `Collection.execute_managed/6` once per candidate. No
receipt, source clock, anchor page or live page is seeded directly. Each success
writes the unchanged candidate plus the actual Normalizer's two metadata
changes, and retains its real managed receipt. Source IDs are generated normally;
there is no search for favorable shards or retry after a refusal.

The maximum-quote fixture constructs a schema-valid **synthetic** operator
observation, then exercises `Input.received`, `SourceIndex.admit_input`, list,
read, quote and handle-based proof resolution. The callback resolves the proof
again immediately before normalization. This authenticates a host-admitted
fixture and its handle, not a human or native terminal event. Session, Consent,
operator input and real inference paths are not exercised.

Each literal quote/text contains 1,024 SHA-256-varied ASCII bytes, with a
256-byte reason. The actual closed note encodes to **3,324 bytes**. It is not
padded outside the native schema, called a 6-KiB payload, or claimed to maximize
every possible JSON-escaped shape. A separate typed-outcome control uses actual
`ToolLifecycle` constructors, source receipts, SourceIndex admission and proof
resolution for a synthetic tool outcome. Its short factual metadata text is not
inflated or mixed into the capacity payload population. No real tool runs.

## Keep unsupported journeys visible

The capacity population contains ordinary literal notes. Preference/current
construction is covered separately by the pure tests. No pin was substituted
with another persistent class. The current Normalizer supports a new literal
or pending proposal; pin/history, correction, deletion, typed acceptance and
operator overrides require separate host journeys. Expiry pruning, no-renewal
recapture, sustainable suppression metadata, actual Sources/Session integration,
two-process writer contention, migration, 2,000/4,000 capacity and annual domain
turnover are not proved here. Every report keeps overall qualification false.

A later bounded continuation design may bootstrap only from this successful
report, exact runtime binding and known closed root digest after complete
canonical record/receipt validation. It must not invent the discarded historical
in-memory normalization map. The original report supplies 186,636 ms elapsed,
but no original wall-start timestamp: exact chronological timing can start at
bootstrap only. Any later approved evidence must retain that distinction and
freeze all continuation bytes before publication. The old interrupted annual
store and its pending marker remain untouched and excluded.

The [artifact manifest](managed-storage-artifacts.json) binds these retained
reports, logs and the three developer source/test files. Relevant operator and
developer collection manuals were reviewed as whole documents; they already
distinguish host primitives, unavailable operator journeys and qualification.
No plan checkbox or user-facing behavior changes in this checkpoint.
