# Batched recall read probe, 2026-11-02

This author-run synthetic probe follows the [bounded replay computation](recall-replay-capacity-20261102.md). It tested whether the existing protected Collection `scan` operation could reduce the repeated worker handoffs in the [33-note diagnostic](recall-many-native-20261102.md). The runtime prototype was not retained. This result does not qualify recall or settle the reason for the underlying failure; the [plan](../../plan.md#p31-usable-knowledge-and-prompt-assistance) retains the open gate.

The [prototype patch](recall-batched-read-prototype-20261102.patch) applies to `34b21c0a`. It changed automatic seed recall to request up to four current records in one existing bounded scan. Each returned record had to match its indexed key, revision, hash and byte count. A confirmed batch refusal fell back to an individual read; an unknown batch outcome cleared the selection. Search continued to use individual reads. The prototype retained the existing 32-candidate limit and did not change host permissions, source checks or deadlines.

The independent worker suite passed all 22 inner tests (outer seed `791932`), including short pages, refused sources, changed records and unknown outcomes. `./dev/build.sh` built the candidate native artifact. The actual synthetic 33-note source control then failed before provider dispatch: five worker inputs were delivered and the sixth was unknown, followed by cancellation with cleanup unconfirmed (seed `791933`, 86.7 seconds). The fixture expected the existing 32-note partial selection; it did not test expanded selection. Its source setup and model request are synthetic, with no live inference.

The outcome shows that batching alone did not make this native journey reliable. It does not prove a precise timeout cause or establish how many notes were successfully selected. The prototype and its fixture changes were removed from active source rather than promoted on the strength of the pure worker tests. Further work must preserve the original current-source checks and bounded ownership while addressing the protected handoff failure, then demonstrate both fitting-set coverage and loss/refusal behavior through the actual Session.

After reverting the prototype, `./dev/build.sh` rebuilt the active artifacts. `git apply --check` verified that the retained patch applies to the recorded source, and the documentation checker reported no errors in a sanitized mirror.
