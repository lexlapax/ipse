## Replace the primitive seed with actual source production

The [selected workload](workload-change-count-20261102.md) retains 2,000 initial
active notes and 200 persistent records before normal annual use and 10,000 mixed
changes. Older workload tools use trusted source/metadata fixtures or generic
batched inserts, so their counts cannot establish native statement/category
admission. The new `NativeNotesSeed` runner uses actual Session input observation,
staging, native statement/category input, ordinary capture and standalone native
pin review. An unexpected model call fails. Neither a checkpoint nor a source
shape supplies a permit or source attestation.

The complete plan has 2,000 captures and 100 separate pin effects: 100 pins,
50 preferences, 50 current assertions and 1,800 remaining ordinary notes. The
2,100 publications use 21 seed days, 100 effects/day and 273 segments of at most
eight effects. The existing public grant and limits are unchanged. Those initial
pin effects are additional to the older capture-only arithmetic floor; expiry,
renewals, imports, cleanup and the complete annual ledger remain to be counted.

Initialization freezes the developer source, SDK/dependency BEAMs, shipped assets,
native helper, PTY driver and process-clock fixture. Its private copied Runner
adds only the two existing clock variables to the two stdio environment maps;
the actual protected child must prove wall-clock coherence and exclude an
unrelated canary. The machine/kernel and production files remain unchanged.
This reuses the earlier [controlled clock](native-clock-late-supersession-20261102.md)
rather than claiming an unmodified-host time jump.

Every segment starts a fresh OS process/Session, checks prior source hashes,
the exact previous root and all visible public values, then produces new actual
native inputs. It requires confirmed Session close, strict Saved/release claims,
signed metadata/category/clocks for affected records, exact Collection IDs/floor,
settled resource counts and the expected staged-publication count. It measures
native staging allocation, capture elapsed time, post-segment BEAM memory and
Collection/control/identity/source-session/management-journal allocations.
Samples are not whole-process-tree RAM peaks or reference-hardware latency passes.
The full-source journal cost is reported separately from Collection value objects.

A parent-observed exit-zero result closes each verified checkpoint. Failure
retains `inflight.json`; later execution refuses instead of replaying or deleting
unknown liability. Completed plans and changed frozen bytes also refuse. A
16-million-word driver heap bound and the existing per-segment PTY deadline
constrain execution; product storage/profile/permission bounds remain intact.
