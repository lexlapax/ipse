## Complete context within existing limits

Version-four `model.complete` carries a required separate context of 1..8192
UTF-8 bytes, a structured response schema and the existing 120000-ms request
ceiling. Instruction, question and output bounds and the complete 16-KiB SDK
object bound remain unchanged. Both request and complete host-call envelope must
fit, including escaping; overflow refuses without shortening evidence. Versions
one through three retain their prior bytes and limits. Inference, preflight
admission and historical projection share one request dispatcher. Context stays
labelled user data and confers no source authority or permission. Ordinary
approval, managed dependency inheritance, egress, accounting and output release
remain owned by the existing host boundaries. Decision outer operations still
refuse model inference and context publication.

The earlier actual six-note baseline and four-note candidate pack fit complete
context under the existing bound: 6311 and 4417 bytes respectively. This is a
historical byte measurement, not an answer, quality or current-use verdict.

while awaiting its native channel. The second reached approved helper execution
but the terminal consumed an asynchronous watcher reply. The third passed its
interaction checks but applied an idle-only journal assertion after close, where

current and denial passed, while the negative assertions confused interactive
exit status with a service outcome and an unresolved pending action with an
explicit unknown-result flag. Its **2/4 aggregate remains failed**. The fifth
