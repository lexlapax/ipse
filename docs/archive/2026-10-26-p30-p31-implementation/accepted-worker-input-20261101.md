existing display adapter, while admitting versions 3–6 only for the Worker path.
The display adapter still refuses accepted-decision dependencies. Actual signed
links are discovered under current protected ownership, then their original
committed management journals are acquired outside Identity/Consent. Final
protected observation reproduces the records, exact current dependency union
and original Session proofs while all those journal owners remain held.

`PendingAcceptance` retains a bounded ordered group of exact original journals.
Same-process opaque tokens bind individual links; duplicate links share one
owner and conflicting identities for one journal refuse. Tokens remain one-use
through export/settlement and are removed at scope exit. No serialized receipt,
foreign process, arbitrary descriptor or worker-selected journal creates a lease.

The actual pending-input publisher imports these journal descriptions into the
same existing native transaction that already retains Identity, Consent,
Collection, consuming Session flock, Session/Writer controls and inactive
original Session sources. The existing `Z` transfer and `p/w/q` sealed input
protocols are unchanged. Journals close before source/control settlement and
Writer thaw. Only complete settlement permits callback release, under the
original Worker deadline. Failed settlement remains unknown without replay.

Transferable original Session and management-journal readers now use the existing
128-entry source reserve instead of starving the ordinary 32-resource pool.
The combined original Session-group and management-journal count remains at most
128; the native importer additionally retains the one consuming Session
description, within its unchanged 129-source bound. No limit, effect permission,
new dependency, native writer or SDK-selected lease was added.

A genuine two-capture journey exposed a second boundary. The first capture could
finish, close and resume. The second proposal physically saved and its Worker
input/output settled, but model continuation refused the union of earlier root
metadata and the exact successor already authenticated for Worker delivery.

The model-only candidate now accepts this narrow composition when every original
causal write dependency has the recorded mapping to that exact cached successor,
the complete old union still passes the original root-only candidate, and the
known successful own action and freshly inspected adjacent receipt agree.
Projection retains the full original-plus-successor plan commitment, appends the
existing historical notice and leaves original messages unchanged. Worker
admission retains its strict single-old-root predicate. Missing/incomplete
mappings, unknown actions, another fresh root, record contents and unclassified
dependencies cannot use the composition. Existing record families/replay checks
are reused; no new projection authority or journal version was invented.

The pure candidate control preserves the strict Worker's mixed-root refusal,
requires actual mappings for every original write dependency, and refuses
missing writes, unknown outcomes and forged successor generations. The genuine
Session asserts successful second-turn completion, chronological Saved
reconstruction and the explicit generation-1-to-2 historical notice.
