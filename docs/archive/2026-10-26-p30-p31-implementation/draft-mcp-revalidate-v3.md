# Private MCP revalidation replay checkpoint

Historical experimental evidence, 2026-10-27. This is a private prototype, not production behavior or milestone acceptance. It supersedes `draft-mcp-revalidate-v2.md` and applies to commit `52652f825e7437ac32ac630092b69095d2049a3c`; current scope is in `docs/plan.md`.

The scoped independent V2 review found no additional concrete bypass under the trusted-journal assumption, but the author found its replay validator did not bind revalidation event session IDs to the stored snapshot when called without an explicit session ID. V3 adds that binding and tests a changed session ID. It also exercises an actual synthetic server discovery timeout, which records `unknown` and does not dispatch the model. Active cancellation, owner death and restart, matching discovery, catalog drift, correlated journal rewriting, replay ordering and the 16-attempt bound remain in the synthetic native-terminal fixture.
