# Native knowledge capture component

Dated **2026-10-26**, after protected SDK `aa4228e`. This records a developer
integration component, not P31D0/E acceptance or a release. Current implementation
is taught in [knowledge training](../../developer/knowledge-extensions.md#follow-protected-capture-from-a-session-source);
the [plan](../../plan.md) owns remaining delivery gates.

## Implemented boundary

The independent `knowledge/native` SDK-2 artifact reads and quotes a Session
source, constructs a public SDK proof, checks saved lineage override metadata,
deduplicates an existing record, and submits a constrained create-only commit.
The host independently reconstructs evidence and current authority. Exact native
observations can become attributed notes; weak, paraphrased or assistant claims
stay pending. Typed tool outcomes support only their literal text as ordinary
notes. Exact quotation does not establish semantic correctness or category truth.

Capture neither renews existing TTL nor retries conflict/unknown effects. Pending
proposals retain original evidence, a seven-day deadline and a 64-record/256-KiB
retained queue limit. Expired entries still count. Retention metadata wraps its
pure policy with separate native operator evidence; bare/malformed/cross-lineage
or weak-origin wrappers refuse. This is a storage format, not operator acceptance.

Source/package build hooks prepare a compatible precompiled artifact and an inert
digest-bound catalog. Generic `Extension.Bundles` inspects manifests without
loading code and explicitly imports a selected artifact through the existing
Artifact adapter. Import grants no trust/activation and writes no configuration.
Existing Corpus/Graph/Research builds retain their separate selections and helper
closures. No dependency or model call was added.

## Independent adversarial repair

The [independent audit](capture-sdk-audit.md) found a P1 before the first component
commit: literal recapture applied an anchored ordinary/duration override, while
the pending branch gave a paraphrase a fresh seven days. The repair applies the
existing Notes retention policy and eligibility check before either branch and
caps pending expiry at the earlier operator deadline. It also keeps the proposal's
assigned category ordinary under an ordinary/duration override. Session-only
suppression and the default seven-day proposal ceiling remain enforced.

The auditor's unchanged controls failed exactly two cases before repair and
passed all five afterward. Its 41-test source/SDK/actual-bundle baseline passed
before and after, and independent read-only-outer `--yes` state-put/delete cases
passed. The complete original frozen inventory of 697 files rehashed unchanged.
Root's additional literal/paraphrase/category/deadline regression and isolated
worker cases passed nine parent cases, seed 312803; the worker child has six
checks. The final broader set then passed all 24 cases above. No model calls
were used.

## Remaining scope

Standalone setup/review, explicit proposal acceptance, automatic turn hooks,
managed recall/retraction, correction/forget UI and expiry collection are not
implemented by this component. The one-lineage override layout does not establish
annual metadata sustainability. Package hooks were exercised directly; complete
package/installed/platform and human evidence remain separate checks. Quality and
live main/local-model qualification remain open. The incremental independent audit
does not substitute for the
required final post-implementation audit.
