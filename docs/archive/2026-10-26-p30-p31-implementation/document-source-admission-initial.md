## Explicit binding and live admission

The fixed operator document binding retains exact v1 compatibility. Version 2
adds only `source_use: "shared_producer_v1"`. Under that explicit selection every
embedding create requires a closed `source_guard`; omitting it cannot take a
legacy path. A guarded request under an unselected/v1 identity also refuses.
Read-only `embedding.profile` remains available. Guarded embedding requests stay
version 2 with their existing selection pin, at most two inputs and unchanged
version-2 results. The [worker cohort](shared-producer-guarded-wire.md) preserves
exact claim key/revision/logical hash and four known batch positions.

Host resolves the actual existing project outside Session, then Session binds
project, namespace, document profile, operator choice, full identity, Session and
request before ordinary approval. Embedding effect binding v2 carries that closed
source binding. Actions/Saved compare its Session ID to the authenticated embedding
namespace as well as identity/profile/request; replay validates historical data
but cannot recreate a live dispatch capability.

`Session.DocumentEmbedding` records only newly validated, durably committed live
action results. One original `value.prepare_inline` at expected revision zero and
its exact single-stage commit establish the claim origin. A pending record or a
restored result list cannot establish it. The actual retained reader must later
match that origin's native committing operation/revision/hash/project/namespace.
Each batch spends the expected position in Session before authorization. Only
its matching durable successful embedding result advances; denied, uncertain,
duplicate or mismatched outcomes poison that volatile path. A second prepare
cannot renew the original origin. This is one claim and at most four positions,
not a durable workflow or retry grant.

Registered dispatch has a distinct plain `EgressGate.capture` branch for document
source use even when the notes dependency union is empty. Unregistered routes
refuse. Mixed managed-note/document-source inference currently refuses rather
than bypassing the existing owned notes transport. Actual serialized target/body
hashes meet the gate immediately before the one Finch request. Its callback
returns to the existing Session-owned inference task, which runs a tracked
file effect under short Identity → Collection ownership. It authenticates the
stored relation, rechecks exact active Session/Registry/wire/route authority and
spends the batch. Only after those blocking checks does one trusted UTC sample
check every source and Registry expiry. The gate also retains the minimum of the
original extension output clock and request monotonic timeout. Locks release
before long IO; already admitted remote work retains its in-flight liability.

limited bindings to v1; that failed before the Session/claim/inference. Another
attempt expected immediate source publication where the public bounded protocol
returned a known draft continuation. A later fixture lacked a registered route
and correctly refused before inference. Those failures are retained separately;
no old effect was replayed.

With the corrected configuration, complete inventory and registered loopback
route, the next actual run reached a real pending native claim, approved embedding
intent and dispatch intent, then failed before the fixture observed an HTTP body.
That failed home was removed by the earlier fixture teardown; its copied complete
synthetic journal remains, and future evidence runs preserve failed homes.
A pure reconstruction of successful journaled actions authenticates the logical
relation and live claim-state algorithm. It is not a native reinspection and
does not prove zero bytes reached the wire. The remaining fault is being narrowed
at the actual retained-read/Session-RPC/transport seam using a separate bounded
diagnostic graph. No actual successful producer send, approval-expiry zero-egress
qualification, public page activation or full workload is claimed.

Full capacity, remaining producer pages/facts/group progression, GC/migration,
