## Reason for this change

The unanswered historical-display proposal does not authorize relaxing the
current strict disclosure rule. Implementing that existing rule remains within
the authorized goal. Source inspection found two concrete integration gaps:
the existing Session/Host bridge admits synthetic purposes under an active
extension job, while an ordinary model-tool approval has a different owner and
phase; ordinary current-use observation also closes its Collection read before
entering the use callback. Removing the current refusal or treating arbitrary
retained locks as authenticated policy roles would not resolve either gap.

`ManagedUse.with_display_dependencies/3` supplies the second prerequisite using
the existing validators and owners. It rederives the canonical current union,
verifies its original sources under transferable source locks, repeats signed
metadata/current-policy checks, then opens and retains the actual Collection
owner. Its root must equal all observations. The three returned transaction
capabilities must match the actual Identity, Consent and Collection callbacks
and their original owner; no synthetic role slots substitute for these checks.
`ObservedRead.root_identity/2` exposes the existing structural projection so the
held witness and earlier observations use one validator.

The callback receives exact proof/group tokens, active-source status and wall/
monotonic deadlines bounded by the earliest policy/source limit and five seconds.
Failure, exception, owner loss or late completion after callback entry remains
unknown. Before-entry failure discloses nothing through this callback. Existing
ordinary `with_dependencies/3` behavior is unchanged. Accepted decisions remain
outside this preparation path because their additional original management
journal must also be transferred; the method refuses them rather than omitting
that owner.

This component displays no bytes and grants no execution or output permission.
The actual Session, purpose, complete payload and native sink still need binding;
active original proofs need their actual sealed Writer/Session lock share. Every
native export needs settlement/cleanup, display locks must release before human
wait, and execution must revalidate afterward. Ordinary managed approval gates
remain closed. This component does not qualify correction, supersession,
delegation or worker-pipe result delivery.
