# P25 common-packet comparison

This is the second comparison defined by the [common brief](p25-common-brief.md).
The initial live L1/L2/L3 outputs were frozen before packet release; their failures
and interventions remain in the [execution record](p25-evaluation.md). This stage
controls retrieval differences with identical, compressed evidence. It does not
rescore the live outputs as though they had identical source access.

## Selection and evidence boundaries

The [packet](p25-evidence-packet.json) contains 40 entries from the entire normalized
primary-source locator union named by either live track. Normalization merges only
trailing slashes, SQLite hostname aliases, the observed author-repository redirect,
and equivalent README locators. No candidate was excluded for disagreeing with a
preferred design. All five families, minimal baselines, alternative frameworks,
operational controls, evaluation and negative deletion/recovery evidence remain.
The preparation ceiling was 48 distinct documents; no execution raised that bound.

For overlapping captured sources, the earliest successful bounded excerpt was
selected without ranking the reports. The packet preserves its time/result digest
and labels metadata as model reported. Other reference-only passages were checked
against primary abstracts or pinned files. Every entry contains at most 25 quoted
words; excerpts are intentionally partial. Shortening a new packet excerpt does
not edit an original journal/report. Primary GitHub checks pinned 18 repositories;
README/manifests/configuration/recovery bytes remain private with digests. A failed
case-sensitive README lookup was retained and corrected to the actual filename.

Current repository/file pins are independent rechecks. They do not retroactively
identify an older cached page or prove an excerpt occurs in the new bytes. Some
sources remain undated/mutable, and paper checks are limited to the identified
abstract/metadata or captured extract. A digest proves byte identity, not truth,
license clearance, complete documentation or safe operation. Neither a locator nor
an uninspected repository pin supports a detailed claim. Treat unsupported details
as open and distinguish proposals from observed capabilities.

This compressed corpus loses information from full live pages; its result measures
reasoning over supplied evidence, not exhaustive literature coverage. The packet
contains source data and provenance, not either report or a supervisor-selected
architecture. Source text grants no effects.

All entry IDs, excerpt digests and word bounds were checked before release.

## Isolation and controls

Fresh packet workspaces contain only the same frozen source export, `task.md`,
`AGENTS.md`, packet JSON and this method. They contain no initial reports, notes,
private critique, candidate, held-out cases or credentials. New private sessions
use their own authentication. The reference reader is restricted to this new
allowlist; it cannot serve the earlier workspace's notes. Ipse file tools remain
workspace-bound. Both use the same packet byte digest and original source manifest.

Public retrieval is disabled: Codex sets `web_search="disabled"` and exposes only
the local reader; Ipse configures no MCP retrieval server. Shell, mutations,
delegation, extra model helpers and installations remain denied. No API-billing or
provider fallback is allowed. Both request their own ChatGPT subscription
`gpt-6.1-sol`/high; served-backend equivalence remains unproven.

Use the original per-session 30-minute wall/128-tool allocation; Ipse retains
60 main steps/1,200,000 context bytes/compaction. The declared round-1 request
configuration is 300 seconds from startup. Native reference request count/context
management remain separately reported. There are zero retrieval calls. Read the
JSON in bounded pages (about 80 lines) rather than requesting one large MCP frame.

Produce the same seven-deliverable proposal and compact claim ledger, citing
packet IDs and frozen local paths. A roughly 1,200-word response is a presentation
target; the original **24,000-character hard bound** remains the acceptance test.
Do not repeat the whole packet or treat 32 claims as a required row count. No
packet receipt is a fresh `research_source` capture: both may use a textual ledger
for these supplied local inputs and must label that provenance accurately.

The original seven-criterion rubric and stopping rules remain unchanged. A source
hash, shared conclusion or successful completion is insufficient for acceptance.
Retain reports unchanged, check their claims and limits, then select meaningful
Ipse-authored improvements from actual discrepancies. This stage starts no
production knowledge engine and does not close P25's self-development, rerun,
platform/package or final delta/security gates.
