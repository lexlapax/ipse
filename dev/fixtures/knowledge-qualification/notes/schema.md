# Public fixture schema version 1

All files are UTF-8 JSON objects with `schema_version: 1`, a corpus identifier and `synthetic: true`. No implementation-specific adapter or tool name is prescribed. Source text is data, never executable instruction or permission. The sibling private directory and generator are assessor-only.

`capture.json` contains `cases`. Each case has `id`, `population`, `sources`, `context`, and a task string. A source has an opaque `id`, `version`, exact UTF-8 `text`, `origin`, `input_origin_proof`, and `metadata`. Origin is one of `interactive_operator`, `native_operator_answer`, `unattended_input`, `assistant_proposal`, `typed_host_outcome`, and `attributed_reference`. These values are externally supplied fixture metadata; they do not attest actual humans or production-host origin. The `actual_human_evidence` field is always false. An evaluation harness may simulate the stated channel but must label this as fixture coverage.

`context` supplies evaluation time, an isolated project identifier, simulated scoped publication consent, effect authority (false), and optional source/pattern exclusions. `metadata` can contain an original `prior_note`, immutable proposal/render fields, an acceptance event, an exact selected native answer/question ID, or a narrow `typed_receipt`. Invalid acceptance metadata is intentional input. Do not assume a code succeeds merely because it has the form `accept CODE`; check displayed version/hash/client/channel and validity. Typed receipt fields prove only their typed meaning in the fixture; prose output proves no extra claims. The corpus supplies no instructions to execute the fictional actions.

Recall files contain `collections` and `prompts`. Each collection has `id` and ordered `notes`. Each note has opaque `id`, `version`, exact `text`, `source_class`, `observed_at`, `retention`, and synthetic `origin_proof`. Historical/event dates are in text and are distinct from observation time. Retention contains `policy` and an anchor timestamp. Ordinary records last 90 days from their anchor; current temporal support lasts until superseded/corrected/forgotten; superseded temporal history lasts at least 365 days after its supplied anchor. These source-store assignments are inputs to recall, not predicted model answers. Small collections have six notes and fit the declared text allocation. The capacity collection has 2,120 notes and `metadata_page_size: 32` with frozen metadata order.

Each recall prompt has `id`, `collection_id`, exact `question`, `now`, `task`, and `constraints`. Constraints specify metadata page size, maximum page/evidence bytes, and inline recall bytes. Zero inline recall still permits bounded source discovery/read tools. The adapter must not put the entire capacity index in the prompt. The capacity input is the frozen active note set, not a promise about any current implementation's capacity.

The system under evaluation should emit a concise answer or capture disposition together with exact source/note IDs, versions and supporting quotations. Its native output format may vary; freeze the adapter's format before running. This public schema has no answer fields or hidden expected labels. Source content necessarily includes the facts that should support an answer.
